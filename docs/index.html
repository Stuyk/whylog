whylog

Agents forget everything. whylog writes it down.

Every task leaves a session. Every rule keeps its reason. The next agent reads both before it touches anything. One binary, no dependencies, works with any agent.

macOS / Linux
curl -fsSL https://raw.githubusercontent.com/stuyk/whylog/main/install.sh | sh
Windows (PowerShell)
irm https://raw.githubusercontent.com/stuyk/whylog/main/install.ps1 | iex
$ whylog open "fix duplicate writes"
opened 9f3a
$ whylog note 9f3a "POST retried on 429"
$ whylog decide 9f3a \
"**No retries in the HTTP client**
 - *they caused duplicate writes*"
$ whylog close 9f3a --summary "no retries"
closed 9f3a - 1 file, 1 decision

Agents start from zero. Every time.

They don't know you already tried that approach and threw it away. They don't know that weird setting is there on purpose. So they rediscover everything, or worse, they "fix" something you broke on purpose three weeks ago.

Context

Every task gets a session: what the task was, what got found, what got decided and which files changed. Before an agent starts new work, it reads what earlier sessions decided. It stops agents from undoing each other's work.

Accountability

Git tells you what changed. Sessions tell you why. Something broke? Find the session that touched it and read the reasoning. An agent, you or a teammate, one person or ten at once: everyone leaves the same trail.

One file per task. One log for everyone.

Sessions pile up while you work. Every 25 or so, they get boiled down into a single decision log that every agent reads before it changes anything.

01

Sessions

Every task opens one. Notes and decisions go in as the agent works.

whylog open "<topic>"
02

Compact

whylog tells the agent when 25 sessions are waiting. The agent writes the lasting decisions.

whylog compact
03

Decision log

One markdown file of rules and reasons. Searchable, reviewable in a PR.

whylog why retry

A rule without a reason gets ignored.

So every decision carries both. One line each.

- **No retries in the HTTP client** - *they caused duplicate writes*
The rule

Something the next agent has to follow. A convention, a removal, a revert, "we do X, not Y".

The reason

The part that matters. With it, an agent respects the rule or asks you first. Without it, it argues.

Your agents learn it on their own.

An agent can't use whylog if it doesn't know whylog exists. So whylog init writes a short block into your AGENTS.md, the first thing every agent reads. From then on, every task starts with a briefing.

# once, in your repo
whylog init                # config, sessions folder, DECISIONS.md, AGENTS.md block

# what the agent does on every task
whylog context             # how to run the session, writing rules, recent work
whylog why <topic>         # check past decisions before changing anything
whylog open "<topic>"      # then note, decide, close

# keep it current
whylog agents --check      # fails in CI if the block is missing or stale
whylog skill --install     # optional Claude Code skill

Commands

<id> is the short handle (like 9f3a) or any unique chunk of the session id. Pass - instead of text to read stdin.

CommandWhat it does
contextThe briefing an agent reads at the start of every task
open <topic>Start a session
note <id> <text>Add a note
decide <id> <text>Record a decision
close <id> --summary <text>Finish a session (also takes --files and --decision)
why <words>Search the decisions
compactSummarize sessions that are ready to compact
compact --apply <file> --through <id>Add decisions to the log, delete the compacted sessions
status, list, recentList sessions
agentsAdd, refresh, check or remove the block in AGENTS.md
styleThe writing rules agents follow
init, guide, skill, versionSetup and help

Built for a crowd.

Every session is its own file, named with a timestamp and a random suffix, so any number of agents or people can work at once. Every write is locked and atomic. 60 agents hammering it at once: 420 writes, zero lost. The decision log is plain markdown, so it shows up in pull requests and gets reviewed like any other file.
